# Vault Rules

1. Never document assumptions as facts.
2. Mark unknown information clearly.
3. Keep project state current in `00_HOME/Current Project State.md`.
4. Update the decision log (`04_DECISIONS/Decision Log.md`) after meaningful architectural decisions.
5. Record important problems and verified solutions in `05_PROBLEMS`.
6. Do not duplicate source code inside the vault. Use links and file paths.
7. Prefer links to existing notes instead of rewriting information.
8. Keep notes concise but useful.
9. Preserve evidence for important claims in `99_META/Sources & Evidence.md` or directly inside the decision log.
10. Do not rewrite project history without evidence.
11. Update `00_HOME/AI Handoff.md` whenever the project's current task or status changes.
12. Begin every new AI session at [[START HERE]].
13. Keep [[Hackathon Win Dashboard]] aligned with the official 100-point judging rubric.
14. Add only observed experiments to [[Improvement Changelog]]; label future work `NOT RUN`.
15. Update [[Submission Checklist]] only with verifiable completion evidence.
16. Never let an Obsidian note override current code, tests, Git state, or the source-of-truth hierarchy.
